# 模块设计与调整说明

## 从观察到行动

levels.ts 定义地图，Simulation 保存独立的一局。附近平台先由 Motion.findJump 判断可达性，再由 RulePlanner 根据画像权重评分。模拟器加入任务、访问与受伤记忆，选择目标，执行平移、等待和跳跃，读取反馈后继续决策。GameScene 只负责显示，无画面测试与浏览器共用相同规则。

## 支路设计

第八关 mineNodes 每行依次为中心横坐标、脚下高度、宽度、路线类型、金币。屏幕坐标越小越靠上。编号 0 是起点；1、2、3 是上层钥匙、门、宝箱；4、5 是下层窄桥；6 是上层移动平台；7 为汇合地面；8 是出口。修改坐标或奖励即可调整绕行成本。

任务 key、door、chest 填对应平台编号，保持编号与数组顺序一致。门约束宝藏支路，捷径可绕过。画像名称不参与决策；目前奖励权重加坚持度达到 100 时追求宝箱，这是可解释的人工规则，后续可改成统一效用评价。

## 固定运动能力

MOTION 起跳速度 480、重力 1200，最高上升为 96 像素。地面速度为每秒 120 像素。完整跳跃水平位移固定 140 像素，包含左右方向和不同高度落地。水平速度按“140 / 飞行时间”计算，属于固定距离动作模板。最后一步精确推进到落地时刻，消除帧误差。

起跳前排除提前截住弧线的平台，并预测移动平台位置。平台承载的地面位移另算；错过移动平台后继续竖直下落。修改运动参数必须同步检查地图间距和运行测试。

## 耐心、坚持和记忆

- 耐心控制动态危险前的等待预算：0.3 秒加参数 × 0.035 秒。
- 坚持控制目标受阻后的重新选路时机：0.6 秒加参数 × 0.045 秒，也增加承诺目标得分。
- 记忆记录平台访问、受伤、阻塞；记忆权重越高，重复访问和受伤路线扣分越大。阻塞冷却 3 秒后允许重试。

新一局重新创建记忆和参数副本，不继承上一局经验。任务状态机保证先取钥匙再开门、消耗钥匙、宝箱只奖励一次 30 金币。

## 敌人及验证

EnemyBehavior 中 walker 地面巡逻，hopper 周期起跳，armored 不可踩踏消灭。修改平台 enemyType 选择种类。画面与碰撞共用位置计算。

运行 npm test 和 npm run build。15 项测试保留原七关四画像路线差异，并单独验证双线矿道，不强求每一关四画像都走四条路。相同路线也可能有不同等待、伤害和耗时。npx tsx tools/compare.ts 显示所有关卡种子 42 的结果。

Phaser 引擎使主包较大，当前构建会提示体积，后续可继续拆分加载。
